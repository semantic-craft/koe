# Koe 代码审查标准

供贡献者与编程 agent 在合并前核对变更。按 [贡献指南](../../CONTRIBUTING.md) 和 [交付规则](delivery-rules.md) 记录先红后绿、真实使用情况与未覆盖项目。审查记录应能定位到受审版本、文件与行号、触发条件和运行结果。

## 四阶段审查流程

1. **自动化 CI 与本地门禁。** 日常跑 `./scripts/verify-local.sh --quick`，全量验证走 `./scripts/check`。两个入口均包含 `test_host_contracts.py`、`check_docs.py` 及其回归、`verify-ui-principles.py`、进度校验和 Clippy。CI `test` 的纯文档分流也跑链接与符号检查。按改动核对 SwiftLint 严格模式、iOS 模拟器测试、Android 两个渠道的单测与 Release Lint（含 Compose Lint）及 Ruff、ShellCheck。见 [CI 运行环境](ci-runner.md)。
2. **结构与架构不变量。** 按四层依赖和硬规则 10 追踪意图、持久提交与快照发布。核对 Rust 状态枚举是否穷尽转换、非法状态是否被类型或入口拒绝，及旧代次回调是否隔离。扫描范围内的 Swift、Kotlin 和 Host API 入口单文件最多 500 行。生产业务代码要求零 `unsafe`、`unwrap`、`expect` 与 `panic!`，可恢复错误用显式返回表达。既有 C ABI、系统调用和 Opus FFI 边界逐处审查指针、生命周期、安全注释及 panic 隔离。见 [架构规范](../ARCHITECTURE.md) 和 [硬规则](../../AGENTS.md#硬规则)。
3. **独立跨模型家族对抗复审。** 由不同于实现者模型家族的 reviewer 独立阅读受审 diff、契约和回归结果。优先寻找安全与隐私缺口、并发反例、遗漏的状态机分支、Rust 到原生宿主的契约漂移，以及可删掉的重复状态和抽象。复审记录给出可复核的触发条件、预期行为和受影响入口。修复后重验行为并复核受影响的差异。没有跨家族复审证据时在回执中标明。
4. **人工与真机分流签收。** 维护者按 PR 三项验收签收代码。按硬规则 7，将实体 D3200、签名覆盖安装、系统权限、后台或锁屏等依赖真机的场景列入 `## 需要真机`，另开 `ready-for-human` 工单，写清设备、系统、版本、操作及预期读回。代码过审先合并。模拟器、实包安装与物理设备证据分别记录。见 [PR 模板](../../.github/PULL_REQUEST_TEMPLATE.md) 和 [分流标签](triage-labels.md)。

## 六维代码验收标准

| 维度 | 审查时核对 |
| --- | --- |
| 正确性与状态机不变量 | 正常、取消、超时、重复、过期、失败重试和重启路径保持记录/请求身份。验证持久提交前后状态，涉及核心状态转换时核对形式模型及生产路径的回归。 |
| 架构融贯与硬规则 10 | Rust 领域、服务与 Runtime 各守分层责任。规则、默认值和状态各有一个所有者。宿主渲染快照并发送意图，真实服务与平台 I/O 走各自边界。 |
| 资源与并发安全 | 任务、句柄、锁、队列和订阅有明确的所有者与结束条件。阻塞文件或网络 I/O 退出 UI 主线程，核对有界背压、锁顺序、取消后的尾回调和退出时资源释放。 |
| 确定性复现与可观测性 | 用 `RuntimeEnv` 注入时钟、时区和随机源，用 `FlightRecorder` 保留有界事件。记录脱敏包、隔离回放、受控故障注入及结果断言，分别注明观察到的状态和可重放范围。 |
| 跨端契约一致性 | 对照 Rust 意图、适配器事件、快照、C ABI、Swift、Kotlin/JNI 的 tag、字段、默认值、限额和内存释放约定。用契约门禁和受影响平台的入口验证。 |
| 克制减法与可读性 | 复用已有实现，清理被取代的死代码、无调用者的兼容垫片和重复的 AI 样板。保留有实际使用者的外部兼容契约，并用可复现的行为说明每一层新增复杂度。 |
