# 首次配置与录音任务恢复

对应 GitHub 工单：#8、#10、#13。2026-10-15 实施；模型选型、摘要分析和跨设备同步仍由 #11、#12、#14 跟踪。

## 本轮行为

- 点击尚未配置的云端引擎，直接打开配置窗口。保存不会切换当前引擎，关闭窗口后点击卡片启用。Qwen/豆包表单按引擎建立独立状态。
- 文件任务写入应用文档目录 `AnkerRecorder/file_jobs.json`，保存录音标识、转写类型、配置版本、服务地址、模型、语言和任务阶段；不保存 API Key。恢复时按原服务取当前凭据，服务地址变化时停止执行。
- 排队任务重启后恢复；千问已经保存任务编号时直接查询，不重新上传或提交。上传/提交结果不明的任务显示需重试提示，不自动再次收费。
- 同步服务中断后保留任务和错误，使用录音详情的重试入口。已返回的文字先写入任务记录，再写转写库，完成两步后才标完成；重启可直接保存已有结果。
- 自动 BLE、手动 BLE 和已解密的 Wi-Fi 导出完成后共用处理入口；仅对已转换 WAV、已启用自动转写、已配置引擎且没有转写/已有任务的录音排队。重复完成通知不会再次提交。目录扫描、重命名不会批量触发收费。
- 删除录音同时丢弃任务；排队和执行中的录音限制重命名，其他任务随重命名更新路径。任务记录损坏时停止提交，不当作空队列覆盖。

## 验证与边界

- `test/engine_lineup_test.dart`：未配置 Qwen/豆包打开表单的回归在修复前失败；修复后覆盖保存、显式启用和引擎切换。
- `test/file_job_journal_test.dart`：真实临时文件重开、凭据不落盘、配置固定、未知请求与已知任务、结果恢复、完成去重、删除/重命名和损坏记录。
- `test/qwen_stt_test.dart`：模拟 HTTP 检查提交编号保存后才查询，以及恢复时仅 GET 已有任务和结果。
- `test/recording_processing_test.dart`：控制器恢复排队/已提交/未知/结果状态；自动开关、缺配置、未解码文件、重复取回通知、存储失败不得发请求。
- 本轮测试使用假服务和临时文件，没有调用真实收费 API。双平台编译不等于设备验收。
- iOS 锁屏/切换应用、macOS 休眠恢复、真实 D3200 取回与服务转写仍需 #15/#16 验收。系统终止进程后不会继续运行，重新打开应用才恢复。
- 旧版本仅在内存里的任务无法凭空恢复；新记录从本版本开始建立。不扫描历史录音并自动重提。
- 分析/摘要尚未实现，因此没有新增分析请求或自动分析队列；#10/#13 的分析部分等待 #12 的方案明确。
