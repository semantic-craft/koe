用户希望安克录音豆能够接入手头的 agent，并提供类似 QwenNote 的笔记、转写与会议纪要体验。本次只沉淀经验和开发前问题，不实现 MCP、不连接设备、不上传录音，也不扩大任何 agent 的实际权限。

本地确认项目为 `~/Projects/koe`，Git origin 为 `semantic-craft/koe`，阅读基线 HEAD `fc12765`；所在分支 `codex/cicada-meeting-parity` 有未提交的纪要开发。下述“已有”指项目文档或代码入口存在，不代表本次重新完成真机验收。实际实现前应重新定位当时的代码和数据版本。

QwenNote 事实来自本次接入会话的非秘密交接记录，未在本文编写时重新请求服务。没有读取会议内容、令牌或客户端凭据；不记录未经核验的工具名称、供应商 API 或逆向能力。

## 应带入 Koe 的经验

1. **分层验收。** 连接成功、OAuth 完成、工具列出、实际读取、写入后读回、新会话恢复是不同结果，逐项记录。工具数量只是一时的能力发现快照。
2. **授权范围可见且可缩小。** Koe 候选接口先只读、按录音/项目限制范围；修改标题、校订转写、生成纪要、删除、导出分别处理。上游授权太宽时，网关过滤只能缩小宿主能调用的工具，不能把上游令牌本身变成只读。
3. **持久登录不等于持久操作同意。** OAuth 只保留经用户授予的连接权限；每个新客户端/宿主独立确认信任与可见范围，敏感写入或数据外发按具体动作确认，不因登录过就自动执行。访问过期、拒绝和撤销应有明确恢复入口。
4. **不靠复制令牌扩散接入。** 原则上凭据由一个受控持有者保管，通过合适的认证连接使用。若考虑共享网关，需分别定义上游服务授权、下游客户端身份、宿主文件/网络权限；MCP 能力范围不能替代 agent 宿主权限。
5. **新会话也是交付的一部分。** 记录传输方式、启动/发现条件、运行节点和失效行为；重启与新会话必须重新核验。不能用一个客户端的成功替整个 agent 列表签收。
6. **错误不能造成重复付费或重复写入。** 区分未授权、范围不足、资源不存在、任务处理中、服务离线、请求超时、结果未知和已撤销；结果未知先查任务/版本，不盲目重发。

以上是设计护栏，不是本次已经实现的权限系统。教训的出处、计数和后续验证点见 [教训台账](../agents/lessons.md)。

## 接在 Koe 已有能力上，避免另造录音系统

现有项目身份是 Flutter iOS/macOS 应用，录音豆文档目标为 soundcore Work D3200，另有受限 Android 范围。入口为 [README 架构](../../README.md#架构)、[PROTOCOL](../../PROTOCOL.md) 和 [AGENTS](../../AGENTS.md)。设备型号、固件和配套服务仍须与用户实际设备核对；已有代码和历史协议记录不保证所有固件可用。

| 层 | 现有阅读入口 | MCP 前需要核验的接缝 |
| --- | --- | --- |
| 设备与录音获取 | `lib/ble/`、`lib/wifi/`、`lib/protocol/`、`lib/crypto/`、`lib/state/recorder/device_files.dart` | 配对身份、取回完整性、续录增长、断连恢复；不假定官方 API、云端导出或新逆向路径可用 |
| 原件与持久状态 | `lib/state/recorder/library.dart`、`lib/state/context/`、`lib/state/recorder/material_pack.dart` | 稳定 ID、修订号、回收站、路径边界、进程并发与应用关闭时的读取方式 |
| 转写任务 | `lib/ai/`、`lib/state/recorder/transcription_jobs.dart` | 本地/云端引擎可用性、任务恢复、预算、取消、真实结果落盘；不把请求已提交当完成 |
| 笔记与纪要 | `lib/state/recording_analysis.dart`、`lib/state/meeting_minutes.dart`、`lib/state/recorder/topics.dart` | 区分主题笔记与未归主题会议；来源句段、人工校订、历史和过期标记；当前纪要代码仍在开发 |
| 检索与引用 | `lib/state/context/ask_retrieval.dart`、`lib/state/recorder/ask.dart` | 授权范围内检索、可追溯的录音/句段/时码；空命中不暴露其他会议信息 |
| 对外 MCP | P4 #152–#155（见 ROADMAP） | 服务器进程与存储访问边界、客户端发现、传输、认证、授权和撤销均待设计 |

候选链路为：录音豆 → Koe 取回并保存原件 → 转写任务 → 主题笔记/会议纪要及来源索引 → 有权限约束的应用服务层 → MCP → 各 agent。MCP 提供数据和操作接口，**不会自行把声音转成文字，也不会自行生成摘要**。真正的转写、摘要和纪要由已选引擎或 Koe 的处理流程完成，异步任务结果持久化后再通过接口提供。

不建议让外部 agent 直接读写 Koe 私有 JSON 或设备协议；应先明确可复用的应用服务边界。独立 MCP 进程如何与 Flutter 应用协调、应用未运行时是否可读，仍是选择题，本文未定案。

## 数据、隐私与权限边界

- 延续 ADR 0002：会议默认“录音只留本机”；没有本地转写能力时明确不可用，不偷偷回落云端。纪要默认只发文字也仍是数据外发，应展示目的地和范围；“音频不出设备”不等于会议内容不外发。
- 访问分成元数据、逐字稿、纪要、原音频及写入。优先暴露被用户选定记录的最少文字；原音频下载、批量导出、删除和设备控制不作为第一期默认能力。检索、标题、日志和工具报错也可能泄露会议信息。
- 用户拥有设备不代表已获得其他参会人的录音或第三方处理许可。开发验收使用自录或明确授权的测试音频，先说明转写/摘要服务及其他 agent 的处理范围；未选定的真实会议不用于测试。
- 稳定来源 ID、句段/时码及修订号优先于本机路径；不把原件路径、声纹或凭据返回客户端。声纹按 ADR 0002 仅存本机，不因新增接口进入导出。
- 人工校订和生成结果分开，写入带预期修订号和可追踪操作记录。校订后旧纪要、旧索引应标记失效；并发修改应明确冲突。实际版本模型待核对，不预设字段已经存在。
- 日志只留必要的动作、状态和去敏 ID，不留令牌、全文、原音频或含凭据的 URL；保留期限、删除传播和撤销后的缓存处理需在实施前确定。

## 分期路线与停止条件

| 期 | 工作与交付 | 进入下一期的条件 |
| --- | --- | --- |
| 0：核实与范围 | 核对实际设备/固件、已有取回路径、配套服务/API 的公开资料和可用授权；确定记录范围、数据处理边界与 P4 解冻范围 | 有可重复的合法取回路径与明确数据权限；没有 API 时如实记录，不承诺逆向或云端抓取 |
| 1：只读垂直样例 | 选一条授权测试录音，经已有流程取回、保存、转写、整理；提出最小只读契约（列表/检索/读取纪要及来源） | 原件与来源可核对；接口仅返回指定范围；新会话发现和拒绝访问通过；此时再确定真实工具名 |
| 2：处理任务 | 评估通过应用服务触发转写/纪要，返回任务 ID、进度和结果，覆盖取消与重启恢复 | 请求前记录状态，付费/上传前确认策略生效；结果未知不重发；成功以持久读回为准 |
| 3：受控修改 | 评估标题、笔记、转写/发言人校订及纪要版本更新 | 分离读写授权；冲突、校订保留、来源与旧结果失效策略通过；不扩展到任意设备控制 |
| 4：多 agent | 分别验证 Cindy、Antigravity、herdr、dsh、zcode、Grokbot 的宿主、传输和认证；评估直接连接或 Magpie 网关 | 每个宿主有独立身份/范围与撤销证据，不共享裸令牌；新会话及运行节点分别验收 |

路线并非当前实施授权。分支、工单、PR 与需要真机的独立验收遵循项目规则；不因这份规划新增后台服务或更改冻结范围。

## 开发时使用的验收矩阵

下表是未来验收要求，当前全部未执行；QwenNote 的历史观察仅限上文列出的事实。

| 场景 | 必须看到的证据 |
| --- | --- |
| 首次连接、新会话、重启 | 无凭据时正确发起授权；授权后发现约定能力；新会话能读取指定测试记录并返回版本 |
| 最小权限与隔离 | 只读身份无法写；越界 ID、列表、检索、缓存和错误均不泄露其他记录；各 agent 范围独立 |

| 转写与纪要 | 测试原声→逐字稿→纪要链路可追溯；决策/待办可回到来源；无依据的信息不充当事实 |
| 离线与云端边界 | 本机模式下不上传音频；缺引擎不回落；文字整理或外发符合用户选定范围 |
| 异步、付费与恢复 | 排队/失败/取消/超时可区分；请求未知先查；重启后不重复付费；完成后结果持久读回 |
| 修改与冲突 | 修改后读回、重启保留；旧修订拒绝覆盖；人工校订不丢；原件及来源 ID 保留 |
| 过期与撤销 | 过期明确提示重新连接；撤销后不能继续访问；下游会话和缓存策略符合已定边界 |
| 多客户端 | 每个宿主分别记录发现、读取、受控写入（如启用）、新会话恢复、撤销；未测项明确标记 |

## 实施前仍需回答的问题

1. 用户实际设备是否为 D3200，固件与平台是什么？现有 BLE/Wi-Fi 路径在哪些组合上有当前真机证据？配套服务是否提供公开 API/导出，以及授权是否允许该用法？
2. MCP 面向 Mac 本地代理、手机局域网服务还是远端节点？哪个进程拥有数据、何时可用、哪些端口/文件权限必要？不默认开放公网。
3. 首批只开放哪些录音和字段？只读优先是否足够？谁保管 OAuth/其他凭据，客户端身份、逐次动作授权、过期和撤销如何落地？具体传输与认证方案需对照届时官方 MCP 规范核验。
4. 用户愿意把哪些音频/文字发给哪些模型与 agent？预算、第三方会议许可、存储地域/期限、删除及索引更新策略是什么？
5. 既有 ID、纪要修订、任务状态能否作为稳定契约？独立服务与应用并发时如何避免 JSON 覆盖？哪些边界应复用应用服务而非重复实现？
6. “像 QwenNote”优先指检索读取、生成纪要、人工校订还是跨 agent 调用？应以授权样例的端到端结果定范围，不以 27 个工具数量为目标。
