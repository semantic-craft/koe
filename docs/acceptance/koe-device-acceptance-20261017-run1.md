路径均为容器内 `Documents/AnkerRecorder/exports/<fileId>.wav`。头字段用 RIFF/fmt/data 解析，解码时长用 `afinfo` 复核（仅读元数据，未播放、未转写、未上传）。

| --- | --- | --- |
| 字节数 | 50,509,484 | 12,602,924 |
| RIFF 声明长度 + 8 | 50,509,484（一致） | 12,602,924（一致） |
| fmt | PCM、1 声道、48000 Hz、16 bit、byteRate 96000 | 同左 |

两者 UI 时长都等于 `floor(解码时长)`，旧观察中的 04:37 与 00:25 分别约为最终长度的 53% 和 19%。

### 1.2 杀进程重启前后

同一 fileId 在**重启前**、**三次杀进程重启后**、**升级到 1.1.0 后**的 SHA-256 完全相同（值不入库），字节数与修改时间不变；UI 时长始终为 08:46 / 02:11。

### 1.3 全库一致性

本地 14 条录音逐条比对「WAV 负载字节数 ÷ 96000」与 UI 列表时长：14/14 一致（例：07:38=458.26 s、04:07=247.84 s、00:09=9.92 s）。

### 1.4 iPhone 与 Mac 同 fileId 对照（新发现）

Mac 容器 `~/Library/Containers/com.anker.ankerRecorder/Data/Documents/AnkerRecorder/exports/` 存有同 fileId 的另一份 WAV，同样头结构一致，但长度不同：

| fileId（起点） | iPhone 解码时长 | Mac 解码时长 | 差 |
| --- | --- | --- | --- |
| `1792135112`（15:18） | 526.14 s | 555.46 s | +29.3 s |
| `1792134452`（15:07） | 131.28 s | 233.74 s | +102.5 s |
| `1792133833`（14:57） | 458.26 s | 379.98 s | −78.3 s |
| 其余 8 条共同条目 | — | — | 差 ≤0.7 s |

两端 UI 各自与自己的本地文件一致（Mac 显示 09:15 / 03:53 / 06:19）。

### 1.5 判定

- 已排除：**显示/缓存单独漂移**。同一条录音的 UI 时长始终等于其本地文件解码时长，重启与重装都不改变文件。
- 未排除：**取回/写入过程中的文件长度变化**。历史 04:37→08:46、00:25→02:11 与「第一次读到的是尚未写完的文件」现象一致；iPhone 与 Mac 同 fileId 长度相差 29–102 秒，说明两端保存的音频本身不同，且方向不一致（有变长也有变短）。
- 未证实：PR #98 修复的缓存竞态不是旧观察的根因证据；本轮未触发 WAV 重转，未覆盖该路径。
- 未做：回听核对（不播放私人音频）。

**结论：** `UNCOVERED`（部分排除）。#92 保持 OPEN。

**待补证据（用户真机时同刻采集）：** 同一 fileId 在「录音中 / 取回中 / 结束并落盘后」三个时刻的字节数、修改时间、WAV 头、解码时长与 UI 时长；以及设备端原始文件长度与回听起止。
