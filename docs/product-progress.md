## 产品目标与当前决定

脱离飞书使用 D3200：独立或 App 发起录音 → 完整取回并保留音频 → 指定服务转写 → 摘要与分析 → 阅读、回听和导出。iPhone、Mac 各自可用。

- 转写保留千问 3.1、豆包极速版及实时二遍；摘要、自定义分析和纪要继续用 Qwen3.8-Flash。摘要手动生成，不默认新增付费任务。
- 不接入豆包标准版；不做双端同步或跨录音问答。两端目前独立保存资料，蓝牙交接不等于资料同步。
- 复用已有约 30 秒授权录音；大小、时长与异常边界用自动化检查。真实长时效果随日常使用观察，不要求专门录长音频。
- 代码合并不等待真机；真实 iPhone/Mac、云端模型、分享目标和安装升级由用户统一验收。代码测试、Apple 构建和旧验收报告都不能替代这一层。

1. **用户统一真机验收。** 先记录 App 构建身份（版本、commit、安装方式、设备与系统），再按 #15/#16 做日常流程，按 #71 验收取回、#95 验收 Markdown 分享、#96 验收恢复后文本、#97 验收主题汇总。真实模型调用由用户决定是否付费；失败可复现时再开修复 PR。
2. **#92 时长证据。** 当前代码修复了“重新转换后缓存不刷新”，但旧观察中 15:18 的 04:37→08:46、15:07 的 00:25→02:11 仍不能区分音频追加、重复写入与显示旧值。需要同一文件在重启前后的路径/身份、字节数、修改时间、WAV 头声明长度与 byteRate、可解码/回听时长、App 构建和 UI 时长；只采元数据，不上传音频。
3. Koe 改名文档与跨平台核对见 [改名验收](koe-rename-acceptance.md)：macOS（#36）、iOS（#37）的系统名称已在 main；Android（#38/#62）未合并，启动器名称、图标和通知未验收。安装 ID、数据目录与设备协议标识保留。
