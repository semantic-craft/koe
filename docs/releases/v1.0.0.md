# Koe v1.0.0 发布说明

- **版本号**：`1.0.0+2`（面向用户版本 `1.0.0`，构建号 `2`）
- **适用平台**：macOS、iOS（Android 不在本次范围）
- **适配硬件**：soundcore Work（安克 AI 录音豆 / D3200）

**Koe** 是脱离飞书 App 独立使用的安克录音豆（D3200）客户端，支持在 iPhone 与 Mac 上完成设备配对控制、实时录音与离线音频取回、指定模型转写、AI 摘要分析、结构化纪要与思维导图导出。

本次 `v1.0.0` 首发版本围绕两条核心发布门槛交付：

---

## 一、随时随地记录想法

### 1. iOS 快捷指令与操作按钮入口（[#35](https://github.com/semantic-craft/koe/issues/35)、[#37](https://github.com/semantic-craft/koe/issues/37)）

- **系统展示统一为 Koe**：iPhone 主屏幕、系统设置、蓝牙/本地网络权限说明及快捷指令动作统一使用 **Koe** 品牌名称，同时保留原有 Bundle ID（`com.semanticcraft.soundcore`）、URL Scheme（`soundcore://`）与快捷指令动作标识，覆盖升级不丢失已有数据与自动化配置。
- **一键开始录音**：安装并至少连接一次 D3200 后，可在 iPhone **设置 → 操作按钮 → 快捷指令** 中选择 **Koe → 开始录音**（动作标题为「用 Koe 开始录音」）。
- **离线自动重连与防重入**：从锁屏或其他应用长按操作按钮即可唤起 Koe；若已绑定的录音豆暂时离线，应用会先自动重连（最长等待 30 秒）再启动录音；若当前已在实时录音中，再次触发只会回到当前会话，不会重复发送开始命令。

### 2. macOS 启动、系统身份与双端连接交接（[#9](https://github.com/semantic-craft/koe/issues/9)、[#22](https://github.com/semantic-craft/koe/issues/22)、[#35](https://github.com/semantic-craft/koe/issues/35)、[#36](https://github.com/semantic-craft/koe/issues/36)、[#59](https://github.com/semantic-craft/koe/issues/59)）

- **标准安装与旧包退役**：macOS 应用包、菜单栏与权限说明统一为 **Koe**，默认安装至 `/Applications/Koe.app`。安装脚本在检测到改名前的 `/Applications/Soundcore Manager.app` 时，会先将其完整归档为 zip、校验 SHA-256 与签名后再移除并注销 Launch Services 登记，防止系统或 `soundcore://` 误启动旧副本。
- **系统 Keychain 安全存储与免重复授权升级**：模型 API Key 迁入 macOS / iOS 系统 Keychain，迁移验证成功后清除旧明文配置。macOS 发布构建采用固定 `Developer ID Application`（Team `LQAVR62TK2`）签名并校验证书信任边界，跨版本覆盖升级后保持同一 Designated Requirement，静默读取已有钥匙串凭据而不再反复弹出系统密码授权框；开发与验证构建默认使用进程内隔离存储，不触达个人钥匙串。
- **跨重启保留手动断开与暂停续录**：手动断开蓝牙连接后，断开意图跨进程持久化保留，防止旧端后台重连抢占设备，方便在 iPhone 与 Mac 之间轮流连接；完整识别设备停止、录音、暂停三态，暂停后继续录音沿用同一会话与音频文件。

### 3. 录音取回后自动转写（[#8](https://github.com/semantic-craft/koe/issues/8)、[#11](https://github.com/semantic-craft/koe/issues/11)、[#13](https://github.com/semantic-craft/koe/issues/13)、[#23](https://github.com/semantic-craft/koe/issues/23)、[#25](https://github.com/semantic-craft/koe/issues/25)）

- **精简首次配置**：从无密钥状态即可直接点击打开引擎配置窗口；豆包仅需填写 API Key，通义千问仅需填写 API Key（及可选 Workspace ID），程序自动匹配服务地址与模型，首次保存后自动启用并关闭窗口。
- **多引擎实时与文件转写**：
  - **通义千问 3.1**：实时流式采用 `qwen-audio-3.1-asr-flash-streaming`；文件转写采用 `qwen-audio-3.1-asr-flash-filetrans`，支持分块 Ogg/Opus 封装与磁盘流式上传。
  - **豆包语音**：实时流式采用 `volc.seedasr.sauc.duration`（开启 `enable_nonstream` 二遍识别）；文件转写采用极速版 `volc.bigasr.auc_turbo`，按 100 MB / 2 小时上限检查并优先选择匹配的压缩录音分块流式上传。
  - **Apple 设备端处理**（iOS 26+）：支持在 iPhone 本地完成实时或存量录音转写与单向翻译。
- **取回完整性门禁与统一自动转写入口**：BLE 离线文件拉取与 Wi‑Fi SoftAP 批量导出（BLE ECDH 会话握手 + `1A07` 单文件密钥 AES‑CTR 解密）共用同一取回处理入口。开启「自动转写」时，录音完整取回后自动提交至当前生效的语音服务；传输中断或未完整取回的音频不触发转写任务，重连后可重新拉取并转写一次。

### 4. 任务恢复与音频版本保护（[#10](https://github.com/semantic-craft/koe/issues/10)、[#13](https://github.com/semantic-craft/koe/issues/13)、[#23](https://github.com/semantic-craft/koe/issues/23)、[#64](https://github.com/semantic-craft/koe/issues/64)）

- **跨进程任务持久化与恢复**：通过 `FileJobJournal` 在发起付费请求前落盘记录任务配置与阶段。应用重启或中断恢复后，已获得云端任务 ID 的千问文件转写任务继续查询直至结果落盘；提交状态未知的任务不自动重发，避免重复计费。长文本分析支持分段检查点续跑。
- **音频内容 SHA-256 版本识别**：以音频文件的分块 SHA-256 摘要作为内容身份，重命名录音或刷新目录不会重复触发转写。当同编号录音的音频内容发生变化时，保留原有转写文本与分析结果、标记旧内容已过期并提示用户手动重新转写，且请求途中的迟到响应不会覆盖新结果。

## 二、可灵活接入多种系统提示词

### 1. 可配置的 AI 提示词模板库（[#12](https://github.com/semantic-craft/koe/issues/12)、[#24](https://github.com/semantic-craft/koe/issues/24)、[#27](https://github.com/semantic-craft/koe/issues/27)、[#28](https://github.com/semantic-craft/koe/issues/28)、[#76](https://github.com/semantic-craft/koe/issues/76) / [PR #78](https://github.com/semantic-craft/koe/pull/78)）

- **内置与自定义提示词模板库**：在 Qwen3.8-Flash 驱动的录音摘要、自定义分析、可编辑结构化会议纪要与双端思维导图基础上，新增持久化至 `analysis.json` 的提示词模板库（`PromptTemplate`）：
  - **4 套内置模板（只读保护）**：内置 `默认摘要`（`summary`）、`结构化纪要`（`minutes`）、`读书笔记`（`book-note`）、`思考笔记`（`thinking-note`）。内置模板不可删除，支持一键复制为自定义模板后按需修改。
  - **双端统一管理与运行**：在 iOS 与 macOS 共用的录音详情「摘要与分析」面板中，可直接切换任意内置或自定义模板运行分析，并支持新建、编辑（版本号自动递增）、删除自定义系统提示词模板；结构化纪要面板等模块统一按模板 ID 读取提示词，不再硬编码。
- **模板版本指纹与不自动重跑保护**：分析结果（`AnalysisResult`）与任务指纹同时记录模板 ID、版本号与提示词正文。编辑模板后，既有分析结果仅标记为「模板已更新，这份结果已过期，请重新生成。」，不会在后台自动重跑或产生重复计费；从旧版本升级后，原有的默认摘要、自定义分析指令（`customInstructions`）及分段检查点完整保留并兼容续跑。
- **结构化纪要与思维导图**：纪要生成议题、决策、待办与未决问题，支持人工编辑、原文依据回溯与 Markdown 导出；思维导图直接从结构化纪要生成（不额外调用模型），支持缩放、折叠、查看原文依据与导出完整 PNG。

## 三、安装方式

### macOS

1. **打包与 DMG 安装**（需要本机钥匙串具备唯一 `Developer ID Application` 证书，Team `LQAVR62TK2`）：
   ```bash
   ./scripts/build-dmg.sh
   ```
   构建并完成 Developer ID 签名校验后，产物输出为：
   ```text
   dist/koe-1.0.0-macos.dmg
   ```
   双击挂载 `koe-1.0.0-macos.dmg`，将 `Koe.app` 拖入 `/Applications` 即可。

2. **本机脚本直接安装 / 升级**：
   ```bash
   ./scripts/install-macos.sh
   ```
   脚本会检查并要求先退出正在运行的旧进程，构建 Release 包并用固定 Developer ID 签名安装至 `/Applications/Koe.app`，自动校验钥匙串 Designated Requirement，同时将改名前的 `/Applications/Soundcore Manager.app` 归档至 `~/Library/Application Support/Koe Install Backups/` 校验后移除。`Documents/AnkerRecorder` 下的既有录音、导出文件与配置均保留原处。

### iOS

连接 iPhone 真机后，通过 `scripts/install-ios.sh` 使用 Xcode 开发签名构建并安装：

```bash
./scripts/install-ios.sh
# 指定设备 UDID 并在安装后启动：
./scripts/install-ios.sh --device <UDID> --launch
```

脚本调用 `xcodebuild`（默认 `Release` 配置、`DEVELOPMENT_TEAM=LQAVR62TK2`、`CODE_SIGN_STYLE=Automatic`）完成自动签名构建，并通过 `xcrun devicectl device install app` 安装至已连接的 iPhone。

## 四、已知限制

- **macOS 尚未公证（Notarization）**：`koe-1.0.0-macos.dmg` 与 `/Applications/Koe.app` 使用 Developer ID 证书完成本地代码签名以保证系统 Keychain 跨版本升级授权，但**未执行 Apple 公证（Notarize）与票据装订（Staple）**。在开启 Gatekeeper 的其他 Mac 上首次打开时可能提示无法验证开发者。本 PR 合并不执行签名与发布，合并后由用户签名/公证/发布。
- **iOS 无 TestFlight / App Store 分发**：本次发布**不上传 TestFlight 或 App Store Connect**，仅支持通过 `./scripts/install-ios.sh` 使用 Xcode 开发签名直装真机（受开发描述文件有效期与设备注册限制）。
- **Android 不在本次范围**：Android 端的 Koe 启动器名称、图标与后台同步通知改名（[#38](https://github.com/semantic-craft/koe/issues/38) / [PR #62](https://github.com/semantic-craft/koe/pull/62)）尚未合入主线，也未进行 Android 真机验收，本次 `v1.0.0` 不包含 Android。
- **其他已知边界与待真机复核项**：
  - **无双端自动云同步**：iPhone 与 Mac 各自独立保存录音、转写与分析数据（[#14](https://github.com/semantic-craft/koe/issues/14) 暂缓），蓝牙断开交接仅释放设备连接，不自动同步两端文件。
  - **主题笔记后半段尚未合入**：[#51](https://github.com/semantic-craft/koe/issues/51)–[#54](https://github.com/semantic-craft/koe/issues/54) 尚未进入 `v1.0.0` 主线。
  - **待真机日常复核项**：Wi‑Fi SoftAP 硬件导出与中断恢复、iPhone 主题归类真机交互（[#50](https://github.com/semantic-craft/koe/issues/50)）、双端提示词模板库真机交互（[#76](https://github.com/semantic-craft/koe/issues/76)）及双端完整日常验收（[#15](https://github.com/semantic-craft/koe/issues/15)、[#16](https://github.com/semantic-craft/koe/issues/16)、[#71](https://github.com/semantic-craft/koe/issues/71)）按各工单「需要真机」清单留待安装发布包后在实际使用中复核。
