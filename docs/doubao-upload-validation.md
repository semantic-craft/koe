# 豆包极速版上传优化（#25）

## 行为与依据

2026-10-15 核对[火山官方文档](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelrecordingfileLiterecognitionAPI?lang=zh)：录音文件极速版支持不超过 100 MB、2 小时的音频；20 MB 以内是取决于出口带宽的建议，不是硬限制。文档没有明确 MB 对应的字节进位，本地采用较保守的十进制 100,000,000 字节并在错误提示中明示。大小与时长分别检查。

上传与播放路径分离。已有 WAV 只在同名原始 Opus 的测得时长匹配（容差 500 ms）时选择压缩源；否则沿用 WAV。原始 Opus 分块封装 OGG，不改变记录身份或播放文件。Qwen 和豆包共用这一匹配规则。

Base64 与 JSON 按流发送，固定 Content-Length，不创建完整音频、完整 Base64 字符串与完整 JSON 的多份内存副本。文件读取块约 64 KiB，编码块不超过 128 KiB；响应最多保留 16 MiB。合法 OGG Opus/WAV 进入请求，未知格式明确失败，不把任意字节当音频。

上传进度与识别等待分开显示；可停止等待。取消、超时或网络中断会终止本地请求，明确提示结果未确认、重试需要重新上传并可能重复计费。极速版没有使用断点续传或可恢复查询；已有持久任务不自动重发未知请求，成功结果仍先保存后确认完成。没有接入标准版、对象存储或自动切换供应商。

## 回退测试

- 新增 25 MiB WAV 上传测试在修复前失败于旧 20 MiB 限制（doubao-upload-red.log），修复后完成上传并验证发送块大小。
- 全量 272 项测试和静态分析通过。覆盖 20 MiB 附近、100,000,000 字节边界、2 小时边界、Base64 跨块余数及精确 Content-Length、压缩源匹配/缺失/不匹配、格式错误、取消、超时与文件保留。100 MB 超限夹具为稀疏文件，不为测试分配完整大音频内存。
- 现有模拟 HTTP 测试改为读取真实请求流；旧的伪 OGG 测试头改成完整 OGG Opus 容器。

## 真实使用情况

生产豆包极速版对已有 16:25 独立录音完成调用：播放 WAV 为 2,905,004 字节，匹配原始 Opus 为 242,080 字节；返回时长 30.18 秒、131 字转写，阶段依次 preparing / uploading / processing / fetching。原录音路径保持不变。证据位于忽略目录 build/device-validation/doubao-upload-live-evidence.json，不提交录音、全文或 Key。

本版两端安装及界面检查将在合并后补记。

## 没跑到的项目

按用户要求没有专门录制长音频，也没有用 100 MB / 2 小时音频发起真实付费请求；真实长时准确率、慢网极限和内存峰值不宣称已验证。自动化验证请求块与取消/超时行为，实际长时稳定性留待日常使用。没有重新执行 BLE 独立录音取回操作，本次复用既有短录音。
