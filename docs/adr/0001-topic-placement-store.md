# ADR 0001：主题与录音归属用独立的本地记录保存

- 状态：已采纳（#50，2026-10-16）
- 相关：#49 规格、#50 实施；后续 #51–#54 在此基础上扩展

## 背景

主题笔记要给录音加一层“属于哪个主题”的归属，并支持当天有效的当前主题。现有数据分散在三处：录音音频与 `exports.json`（导出目录）、`transcripts.json`（转写）、`FileJobJournal`（付费任务阶段，读失败时拒绝启动付费工作）。要求：重启后一致；记录损坏时不丢录音；未归主题录音的现有流程不变；第一版只做 iPhone。

## 决定

1. 新增 `TopicStore`，单独保存为 `AnkerRecorder/topics.json`，内容只有主题列表、当前主题（主题 id + 设定当天的本地日期）和“录音键 → 归属”映射。录音键与转写、分析共用（`file:<设备文件号>`，没有文件号时 `path:<路径>`），改名不影响文件号键，删除录音时同步删除归属。
2. 归属是单值映射：`topic:<id>` / `pending`（待归类）/ `none`（用户移出主题）。一条录音因此结构上只能属于一个主题；已有归属的录音再次取回不会被改动。
3. 归类只在 `processRetrievedRecording`（BLE 与 Wi-Fi 取回共用入口）执行，且先于“自动转写”开关判断，不新增任何付费调用。
4. 当前主题跨日：读取时按本地日期惰性失效并落盘（覆盖冷启动、后台恢复），另设到下一个本地午夜的定时器并通知界面（覆盖前台跨午夜），App 回到前台时再检查一次。
5. 损坏处理“失败开放”：整份无法解析时把原文件改名为 `topics.json.corrupt-<毫秒>` 保留，从空状态继续；部分条目损坏时，指向无效主题或无法识别的归属一律转为“待归类”。
6. `topicsEnabled` 默认只在 iOS 为真；Mac 不加载、不写入主题记录，也不显示主题入口。

## 考虑过的方案

- 把归属写进 `exports.json` 或转写记录：可以少一个文件，但会让主题记录的损坏、迁移和格式演进牵连录音目录与转写；独立文件让“丢主题记录 ≠ 丢录音”在结构上成立。
- 沿用 `FileJobJournal` 的“读失败即拒绝工作”：那是为了防止重复计费；归属不涉及付费，拒绝启动会把整个录音库藏起来，代价大于收益。#51 自动生成笔记会产生付费调用，届时付费任务仍由 `FileJobJournal` 守门，`TopicStore` 只回答“是否已归入主题”。
- 只靠读取时失效、不设午夜定时器：前台跨午夜时界面会一直显示昨天的当前主题，直到下一次重建。

## 后果

- 归属与录音文件之间没有事务：删除录音时先删文件再删归属，中途失败最多留下一个指向不存在录音的归属，界面按录音库过滤，不会显示。
- 主题记录不跨设备同步；Mac 与 iPhone 各自独立。若以后 Mac 显示主题，需要另立同步方案并更新本 ADR。
- 设备时区或系统时间改变时，以读取时刻的本地日期为准判定是否跨日。
